01 / CONCEPT
What is this project?

The Problem We're Solving

Games like Elden Ring, Warframe, and Helldivers 2 have complex character builds — stat distributions, weapon choices, armor combinations.

Right now, players share these builds through scattered Reddit posts, Discord messages, and screenshots. There is no dedicated, structured place to store and browse them.

The Tarnished Vault is a REST API that acts as a centralized database for these character loadouts — supporting both structured stat data and visual screenshots.

⚔️

POST /builds

Submit a character loadout — stats in JSON format, plus an optional screenshot image file.

🖼️

GET /builds

Retrieve all community builds. Each entry includes stats AND a direct image URL from Azure Blob Storage.

Step 1

Client sends request

A multipart/form-data POST containing a JSON body (stats, title, game) and optionally an image file (the screenshot).

Step 2

API routes the data

The .NET API separates the JSON from the binary. JSON → CosmosDB. Image → Blob Storage. The returned Blob URL is embedded into the CosmosDB document.

Step 3

Background event fires

The Blob upload automatically triggers the Azure Function. It runs in the background — the client already got its 201 Created response. No delay.

05 / DATA MODEL
What gets stored

CosmosDB Document Structure

{ "id": "uuid-auto-generated", "game": "Elden Ring", "title": "Dragon Knight Build", "author": "TarnishedWarrior", "description": "High DEX/ARC...", "stats": { "level": 150, "vigor": 40, "dexterity": 55, "arcane": 50 }, "equipment": { "weapon": "Dragon Crest Greatshield", "talisman": "Millicent's Prosthesis" }, "screenshotUrl": "https://blob.azure.com/...", "createdAt": "2026-06-17T23:00:00Z" }

Why NoSQL (CosmosDB)?

Elden Ring has different stats than Warframe. A rigid SQL table can't handle both. CosmosDB stores flexible JSON — each game can have its own fields without breaking the schema.

Why separate Blob Storage?

Storing binary image data inside a database is bad practice — it bloats the DB and slows queries. Blob Storage is purpose-built for files. We only store the URL inside CosmosDB, not the image bytes.
